# Чеклист выполнения требований ТЗ

## Функциональные требования

### 1. Два отдельных сервиса (микросервиса)
- ✅ Order Service - отдельная папка/директория
- ✅ Processor Service - отдельная папка/директория
- ✅ Каждый сервис - автономный процесс

### 2. Order-сервис
- ✅ HTTP endpoint для создания заказа (POST /orders)
- ✅ Принимает JSON с полями: id клиента, список товаров/количество, сумма
- ✅ Сохраняет заказ в реляционной БД (PostgreSQL)
- ✅ Публикует событие order.created в брокер (Kafka)
- ✅ Endpoint для получения статуса заказа (GET /orders/{order_id})

### 3. Processor-сервис
- ✅ Подписывается на событие order.created
- ✅ Выполняет обработку (симуляция успеха/ошибки)
- ✅ Сохраняет результаты обработки в своей БД
- ✅ Публикует order.processed (с полем status и объяснением при ошибке)

### 4. Order-сервис обрабатывает order.processed
- ✅ Подписывается на order.processed
- ✅ Обновляет статус заказа при получении результата

### 5. Взаимодействие через брокер сообщений
- ✅ Используется Kafka для обмена сообщениями
- ✅ Нет синхронных REST-вызовов между сервисами

### 6. Обработка отказов
- ✅ Retry механизм (3 попытки с экспоненциальной задержкой)
- ✅ Логирование ошибок
- ⚠️ Dead Letter Queue - упомянуто в коде, но не реализовано (можно добавить)

### 7. Идемпотентность
- ✅ Уникальный индекс на order_id в Processor Service
- ✅ Проверка существования перед обработкой
- ✅ Корректное применение события без дублирования

### 8. Транзакционность
- ✅ Запись в БД + публикация события (последовательно)
- ✅ Сохранение состояния обработки в БД перед публикацией события
- ⚠️ Outbox Pattern не реализован (можно улучшить)

### 9. Логирование и метрики
- ✅ Логирование значимых событий и ошибок
- ✅ Health-endpoint для проверки готовности сервиса (/health)
- ⚠️ Метрики не реализованы (можно добавить Prometheus)
